# 评测强推理档超时修复说明（2026-09-03）

## 现象与根因证据

V2 开发集校准的前 6 条任务中，轻量档和通用档可以完成调用；一旦动态路由进入强推理档，C4 与 C7 均出现零费用、零延迟的失败，C6 在通用档完成一次调用后升级至强推理档也失败。

初步排查发现，评测调用会给强推理档显式发送 `thinking: { type: "enabled" }`，但网站正式对话的已验证调用方式是在强推理档省略该字段。因此先统一了调用方式。C4 的试次 2 复测仍失败，说明该差异不是最终根因。

为避免继续猜测，已在失败路径增加脱敏诊断日志，并仅重跑 C4 的试次 3。Cloudflare Worker 日志记录为：`errorType = AbortError`、`tier = reasoning`，对应调用在共享的 45 秒客户端超时处被主动中止。该试次的费用与延迟均为 0，说明没有拿到可计费的完整模型响应。

## 修复原因与修改目的

调用方式统一的目的是排除一项已知不一致因素。失败诊断日志只记录任务编号、策略、最终档位、错误类别与 HTTP 状态；不记录用户原文、完整请求、密钥或供应商原始错误文本。

本次根因修复是为评测调用增加可选的请求时限与推理强度，并只在强推理档使用：

- **60 秒时限**：比通用的 45 秒多 15 秒，减少强推理尚未输出就被误判失败的概率；正式聊天仍使用 45 秒，避免影响用户端等待体验。
- **`reasoning_effort: medium`**：保留多约束规划所需的推理能力，同时避免更重的默认推演带来过长等待。
- **600 token 上限**：评测只验证任务约束与能力，不需要输出完整长文；缩短输出可控制成本和时延。

## 修改范围

- 轻量档、通用档：继续显式关闭深度思考，保证成本与速度稳定。
- 强推理档：不再强制传入深度思考开关，由模型服务采用默认兼容行为。
- 强推理评测：使用中等推理强度、600 token 上限和 60 秒时限；正式用户聊天不使用这组覆盖参数。
- 失败诊断：只写入 Cloudflare Worker 日志的脱敏结构化字段，不改变用户端回答，也不改变现有评测记录。
- 不修改模型 ID、密钥、路由门槛、数据集或既有评测记录。

## 验证方式

新增自动化测试：强推理档评测不得强制传入深度思考开关；模型失败时必须写入脱敏诊断字段；评测强推理档必须传入 600 token、60 秒和中等推理强度；模型客户端必须把该推理强度正确传给供应商。新增行为测试均先在旧代码上失败，再在修复后通过。

下一步应在发布后仅重跑 C4 开发集任务一次，确认能产生可审查记录；正式集四策略对照需要单独确认预算后才可开始。
